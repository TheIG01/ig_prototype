# Гайд для новичка: как работает ig_prototype и как его развивать без боли с лимитами

## 1. Что это вообще
ig_prototype это сайт-конструктор для чёрно-белых прототипов сайтов (как Figma + Tilda Zero Block). Ты собираешь структуру страницы из блоков, пишешь тексты, а потом выгружаешь ТЗ для нейросети (Markdown/JSON), HTML одним файлом или PDF для заказчика.

Как он живёт в интернете:
- **GitHub** это «папка в интернете» для файлов проекта. Репозиторий `ig_prototype` и есть эта папка.
- **GitHub Pages** превращает файлы из папки в живой сайт: `https://ТВОЙ_ЛОГИН.github.io/ig_prototype/`.
- **Робот деплоя** (`.github/workflows/deploy.yml`): каждый раз, когда ты загружаешь файлы, он сам собирает проект и обновляет сайт за 1–2 минуты. Если сборка упала, старый сайт остаётся рабочим. Ты ничего не ломаешь.
- Сервера нет. **Все твои проекты хранятся в браузере** (на этом устройстве, зашифрованы твоим ПИН-кодом). Другой браузер, другой компьютер или другой аккаунт видят пустой сервис. Поэтому делай копию проекта кнопкой в сервисе и храни файл.

## 2. Что лежит в папках (как для новичка)
**Корень проекта (главные файлы):**
- `index.html` — самая первая страница, в неё подгружается всё остальное.
- `package.json` — паспорт проекта: название, версия, список «деталей» (React, zustand, immer, lucide-react, vite). Версию (сейчас 1.50.0) меняет ИИ.
- `package-lock.json` — точные версии этих деталей. Не трогай и не удаляй.
- `vite.config.ts` — настройки сборки: адрес `/ig_prototype/` и установка на телефон как приложения (PWA).
- `tsconfig.json` — строгие правила проверки кода (ловят ошибки до публикации).
- `.gitignore` — список того, что не надо загружать на GitHub.
- `README.md` — короткая визитка репозитория.
- `.github/workflows/deploy.yml` — тот самый робот, который публикует сайт.
- `public/icon.svg` — иконка приложения.

**`src/` — сам сервис (код):**
- `main.tsx` и `App.tsx` — запуск. `store.ts` — «мозг и память»: данные проекта (проект → лист → блок → элементы) и все действия над ними (добавить, удалить, переместить, отменить). `styles.css` — внешний вид.
- `src/features/` — экраны, которые ты видишь:
  - `shell/` — шапка, левая панель, вкладка «Слои», настройки, окно отчёта, плашка «Не сохранено», защита от ошибок.
  - `canvas/` — холст (рабочая область), панели свойств элемента, нескольких элементов, блока, рулеры, вставка, правка текста на месте.
  - `blocks/` — библиотека готовых блоков и удаление блока.
  - `quiz/` — редактор квиза. `pin/` — экран ПИН-кода. `preview/` — просмотр прототипа.
- `src/lib/` — «инструменты без экрана»:
  - **Шаблоны блоков** (99 штук): `tpl.ts` (основа), `tplFirst.ts` (первые экраны), `tplLead.ts` (формы заявок), `tplSocial.ts` (соцдоказательства), `tplSteps.ts` (этапы), `tplTeam.ts` (команда), `tplReviews.ts` (отзывы), `tplGuar.ts` (гарантии), `tplManager.ts` (менеджер), `tplQuiz.ts` и `quiz.ts` (квиз).
  - **Выгрузка**: `export.ts` (ТЗ для ИИ), `share.ts` (просмотр и HTML), `report.ts` (PDF).
  - **Хранение**: `vault.ts` и `crypto.ts` (запись в браузер с шифрованием), `tabs.ts` (защита, если открыто две вкладки), `migrate.ts` (старые проекты открываются в новой версии).
  - **Помощники**: `textcheck.ts` (проверка текстов: длина, «вы», «!»), `typo.ts` (типограф), `measure.ts` (автоподгонка размеров), `icons.ts`, `art.ts` (стили, шрифты, фигуры), `ui.ts`, `toast.ts` (плашки-уведомления), `outline.ts`, `select.ts`, `live.ts`, `uid.ts`, `dev.ts` (ПК, планшет, мобилка).

**`docs/` — документы для тебя и для ИИ (на сайт не попадают):**
- `PROGRESS.md` — «где мы сейчас» (ИИ читает первым). `MAP.md` — карта: какая функция в каком файле. `GUIDE.md` — этот гайд.
- `prompts/PROMPT.md` — инструкция для ИИ. `roadmap.md` — план до финала. `work_rules.md` — твои вкусы и правила. `copywriting.md` — правила текстов. `figma_hotkeys.md` — клавиши как в Figma. `first_screen_prompt.md` — твой промпт для первого экрана.
- `refs/` — описания шаблонов и скриншотов словами (ИИ их не читает, пока не попросишь).

## 3. Почему лимиты «улетали за секунду» и что изменено
Лимит тратится не на размер файла (zip ИИ даже не «читает» целиком), а на то, что ИИ **читает и пишет в чате**: длинные документы, большие файлы кода целиком, долгие попытки установки пакетов, многословные отчёты.
Что уже исправлено:
- Удалён мусор: 8 старых копий файлов в корне, архив журнала на 98 КБ, лишние заметки.
- Главный промпт сокращён с 12 КБ до 4 КБ, ИИ читает только `PROGRESS.md` и один раздел плана.
- План сжат с 11 сессий до 8 (убрано редкое и тяжёлое, оно лежит в «Бэклоге»).
- Проверено: установка пакетов, `tsc` и `vite build` работают за секунды, никаких зависаний.
- Сборка идёт одним полным архивом, без «только изменённых» файлов: меньше путаницы.

## 4. Как работать (цикл одной сессии, 3 шага)
1. **Новый чат** в Claude. Приложи один файл: последний `ig_prototype_vX_Y.zip`.
2. Отправь это сообщение (копируй как есть):
```
Продолжаем ig_prototype. Zip приложен.
Работай по docs/prompts/PROMPT.md и docs/PROGRESS.md.
Задача: следующая версия из плана. Сразу делай, в конце приложи один zip.
```
Своя задача: замени третью строку на `Задача: ...`.
3. Когда ИИ приложил новый zip: скачай его, распакуй, залей на GitHub (раздел 5).

**Золотые правила для бесплатного тарифа:**
- Одна сессия = один чат = одна версия. Не продолжай длинный чат, когда версия готова: новый чат дешевле.
- Не пиши в чат ничего лишнего и не прикладывай скриншоты «на всякий случай».
- Лимит кончился посреди работы: подожди обновления лимита, в новом чате напиши **СОХРАНИ** (и приложи последний zip). ИИ запишет прогресс и продолжит ту же версию.
- Не заливай на GitHub каждую версию. Заливай, когда проверил в браузере, что новое работает (раз в 2–3 сессии нормально). Версии копятся в zip, ничего не теряется.
- Файл и аккаунты: проще всего каждый раз **прикладывать zip**. Он работает с любым твоим аккаунтом Claude, потому что всё состояние лежит внутри (`docs/PROGRESS.md`). Подключение GitHub к Claude на бесплатном тарифе не рассчитывай (оно зависит от тарифа и привязывается к одному аккаунту Claude, так что с несколькими аккаунтами это неудобно). Хочешь проверить: в Claude «Настройки → Коннекторы/Интеграции», но zip надёжнее.

## 5. Как залить на GitHub (по шагам)
1. Скачай zip от ИИ и **распакуй** на компьютере (правый клик → «Извлечь всё»).
2. Открой свой репозиторий `ig_prototype` на github.com → кнопка **Add file → Upload files**.
3. Открой распакованную папку и **перетащи в окно браузера её содержимое** (папки `src`, `docs`, `public` и файлы). Не сам zip и не внешнюю папку. Файлы с теми же именами заменятся сами. Папку `.github` перетаскивать не нужно (она уже есть и не менялась), `.gitignore` желательно добавить.
4. Внизу нажми **Commit changes**.
5. Если ИИ приложил `УДАЛИТЬ.txt`: открой каждый файл из списка на GitHub → три точки справа вверху → **Delete file** → Commit. Папку удалить: открой любой файл в ней, удали по одному (либо оставь, она не мешает).
6. Вкладка **Actions**: жди зелёную галочку (1–2 минуты). Потом открой сайт `https://ТВОЙ_ЛОГИН.github.io/ig_prototype/` и нажми Ctrl+Shift+R (обновить без кэша). Красный крестик: сайт остаётся прежним, скопируй текст ошибки из Actions и отправь ИИ.
7. Напиши ИИ **ЗАЛИТО** в следующем чате.

Один раз в самом начале проверь: репозиторий → Settings → Pages → Source = **GitHub Actions**.

## 6. Как довести сервис до «лучшего для прототипов» (после финала 1.56)
1. **Скорость создания прототипа**: сначала собери 5–10 своих реальных прототипов и запиши, где теряешь время. Это важнее новых функций.
2. **Мастер-старт**: выбор ниши (квиз, лендинг, магазин) → готовая структура с твоими текстами по copywriting.md за 30 секунд.
3. **Письмо и ссылка заказчику**: просмотр одной ссылкой (HTML) + комментарии заказчика прямо на макете.
4. **Бриф для ИИ-дизайнера**: сделать «копировать одним кликом» с готовым промптом под Claude/GPT, чтобы из прототипа за минуту выходил дизайн.
5. **Свои шаблоны**: сохраняй удачные блоки из реальных проектов в библиотеку (это самое ценное, что у тебя будет).
6. **Автобэкап проекта**: еженедельное напоминание сохранить копию (данные только в браузере).
7. **Проверка на устройствах**: Safari, Firefox, телефон (сейчас не проверялось).
