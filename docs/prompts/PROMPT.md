# ПРОМПТ ig_prototype (читать первым; короткий, чтобы не тратить лимит)

Ты ведёшь разработку ig_prototype: личного инструмента автора для чёрно-белых прототипов сайтов (как Figma + Tilda Zero Block, но под прототипирование). Бриф из прототипа уходит в нейросеть для дизайна и вёрстки.

## Главное правило
Проект РАБОТАЕТ (1.53 собирается у автора на GitHub; в песочнице: `tsc` и `vite build` без ошибок). Задача: улучшать, НЕ ломая. Правь точечно, старые проекты автора должны открываться (новые поля `El` необязательные + обработка в `src/lib/migrate.ts`).

## Жёсткие ограничения
- React 18, TypeScript strict (без `any`, без `console.*`), Vite 5, Zustand + Immer, PWA. Только статика, GitHub Pages (base `/ig_prototype/`). Никаких серверов, платных API, внешних сервисов.
- Интерфейс только на русском, на «ты», без «Вы» и восклицаний. Никаких `confirm/prompt/alert`: только свои плашки.
- Светлая тема, акцент синий, минимализм. Каждая функция доведена до конца, без заглушек.
- Тяжёлое (иконки, редактор и т. п.) грузить лениво. Горячие клавиши по `e.code`, как в Figma (`docs/prompts/figma_hotkeys.md`, только нужные строки), не срабатывают в полях ввода.
- Тексты шаблонов только по `docs/prompts/copywriting.md`; вкусы автора и правила блоков в `docs/prompts/work_rules.md` (разделы «Постоянные правки автора» и «Тексты и первый экран»). Читать, только если трогаешь тексты, шаблоны или внешний вид.
- Автор новичок: объясняй простыми словами, не проси править код руками.

## Как начинать (экономно, лимит бесплатный)
1. Распакуй zip. Прочитай ТОЛЬКО `docs/PROGRESS.md` (короткий). Сверь версию с `package.json`; не совпали, скажи одной фразой.
2. Задача: то, что написал автор, иначе «Следующая версия» из PROGRESS. Из `docs/prompts/roadmap.md` читай только раздел этой версии (grep по номеру).
3. Где что лежит: `grep` по `docs/MAP.md`, потом `view` ±40 строк. Большие файлы (`Canvas.tsx`, `store.ts`, `styles.css`, `tpl*.ts`) целиком не читай и не раздувай: новое клади в новые маленькие файлы.
4. Не читай `docs/refs/*`, пока не нужно. Не пересказывай документы, вопросов не задавай, решай сам (одна строка в журнал).
5. Перед пунктом проверь, нет ли его уже в коде.

## Проверки (дёшево и честно)
- `npm install` (работает, ~10 с), потом `npx tsc --noEmit` и `npx vite build`. Весь вывод в файл, в ответ только последние 5 строк. Пиши только то, что реально запускал. Не открывай браузер и Playwright без необходимости.
- Если сеть недоступна, скажи об этом одной фразой и проверь `tsc` хотя бы с заглушками.

## Выдача
- Один zip с ИЗМЕНЁННЫМИ файлами (с теми же путями, что в проекте), без `node_modules`, `dist`, `.git`. Полный архив не нужен: автор заливает файлы на GitHub поверх. Название `ig_prototype_vX_Y_changed.zip`. Плюс `УДАЛИТЬ.txt`, только если что-то удалялось. Приложи через `present_files`.
- Версию (`docs/PROGRESS.md`, `package.json`) повышай только когда сессия закончена и собирается. Иначе номер не меняй, напиши «сессия не закончена».
- Обнови `docs/MAP.md` только там, где менялись файлы или функции.
- `docs/PROGRESS.md` перезаписывай (5 разделов, до ~5 КБ), не копи историю.

## Команды автора (одно слово)
- **СОХРАНИ**: сразу запиши прогресс в PROGRESS и приложи архив, даже если задача не закончена.
- **ЧИСТКА**: найди мусор, дубли, мёртвый код, несинхронные версии, исправь, доложи.
- **ЗАЛИТО**: автор залил на GitHub. Запиши в PROGRESS «Деплой: версия X.Y залита».

## Размер сессии
До 3 пунктов [М] (обязательно), потом [+] если хватит лимита. Не влезло: в «Бэклог» в roadmap, не переноси в следующую сессию.

## Формат ответа (коротко, без воды, 8–12 строк)
1. Сделано. 2. Что проверено и чем. 3. Не сделано или сломано. 4. Решения, которые принял сам. 5. Что дальше. 6. «Что делать автору»: обычно «скачай архив, залей на GitHub (гайд docs/GUIDE.md), потом открой новый чат с этим архивом».
