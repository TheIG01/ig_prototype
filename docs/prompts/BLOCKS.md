# Режим БЛОК: скриншоты → чёрно-белые блоки в библиотеку (docs/prompts/PROMPT.md)

Автор приходит с zip проекта и пачкой скриншотов (обычно до 20), в тексте может быть название группы, число вариантов, слово «погоди». Руками автор больше ничего не делает. Ты работаешь молча и выдаёшь готовый полный zip.

## 0. Ввод
- Группа: из сообщения; иначе придумай короткое название по содержимому («Цены», «FAQ», «Контакты»...). Если такая группа уже есть в библиотеке, дополняй её, не дублируй.
- Если фото несколько разных типов блоков, разложи их по группам сам.
- «Погоди, докину»: ответь одним словом и жди. Если автор докинул фото или написал «всё», работай. Число вариантов: по умолчанию 7 (1 лучший + 6 дополнительных), если фото пришли не все сразу или их мало, 10 не нужно: сделай 7. Автор может задать число сам.
- Скриншотов много: смотри их один раз, сразу выпиши разбор в файл `docs/refs/<группа>.md` (таблица: что на экране, раскладка, элементы, чем сильно) и дальше работай по этому файлу, не возвращаясь к картинкам.

## 1. Разбор (коротко, в файл)
По каждому скриншоту: раскладка (колонки, где форма/картинка), состав элементов (заголовок, подзаголовок, кнопки, поля, карточки, иконки, плашки, цифры), порядок важности, что в нём лучшее. Общие закономерности по всем фото: 5–8 строк.

## 2. Вариант №1 «лучший»
Собери один блок из лучших решений всех фото: сильная иерархия, один главный CTA, ничего лишнего, всё читается за 3 секунды. Затем 6 дополнительных вариантов с разной раскладкой (текст слева/справа, по центру, сетка 2/3/4, карточки, список, с формой, с картинкой, компактный). Каждый имеет смысл для своей ситуации (в `tips` одна строка «когда брать»).

## 3. Как строить
- Только чёрно-белый макет: текст, прямоугольники, плейсхолдеры картинок с подписью, кнопки, поля. Без цветов, градиентов, теней и декора. Акцент через размер, вес и обводку.
- Файл `src/lib/tpl<Группа>.ts` с экспортом `<ИМЯ>` (массив `{name,cat,spec:(d:Dev)=>Out}`) и `<ИМЯ>_TIPS`. Образец структуры: `tplLead.ts` (спека → `build`). Движок и примитивы: `tpl.ts` (`render`, `Node`) и `tplFirst.ts` (`ctx`, `r4`, `th`).
- Подключение: ТОЛЬКО `src/lib/tplExtra.ts` (импорт и `EXTRA=[...A,...B]`, `EXTRA_TIPS={...}`). `tpl.ts`, `store.ts` не трогать. Категория в библиотеке появится сама.
- Имена блоков: `Группа: суть` (например «Цены: три тарифа»), без дублей.
- Все элементы обычные (текст, кнопка, поле, плашка), чтобы автор правил каждую деталь.
- Три размера: ПК 1440, планшет 768, мобилка 390. На планшете и мобилке перестраивай, а не сжимай: колонки в столбец, кнопки на всю ширину.

## 4. Качество (обязательно, скриптом в Node)
- Отступы по сетке 8 (4 для мелочей), поля как в `UXPASS.md` п.4, выравнивания по одной левой линии.
- Высота текста считается с запасом (кириллица шире), ничего не налезает друг на друга и не выходит за границы блока, текст не обрезается.
- Тексты по `docs/prompts/copywriting.md`: на «ты», глагол в действии, без «Вы» и восклицаний, цифры вместо слов.
- Проверка перед выдачей: пройди скриптом все новые блоки на 3 размерах (пересечения, выход за края, высота), поправь найденное. В отчёт одной строкой: «проверено N блоков × 3 размера, ошибок 0».
- Скорость: новые файлы грузятся вместе с остальными, тяжёлого не добавлять, тексты в спеках короткие.

## 5. Выдача
`npx tsc --noEmit && npx vite build`; обнови `docs/MAP.md` (одна строка про новый файл), `docs/PROGRESS.md` (группа, число блоков, версия +0.1). Полный zip `ig_vX_Y_full.zip` через `present_files`. В ответе: группа, сколько блоков, 1 строка про главный (№1), что проверено.
